# Security Policy

We take the security of DocReview360 seriously. Please report suspected
vulnerabilities so we can fix them quickly.

## Supported Versions

Only the latest release receives security patches. Please upgrade when new versions become available.

## Reporting a Vulnerability

Use [GitHub private vulnerability reporting](https://github.com/eputnam77/DocReview360/security/advisories/new) to submit a clear
description of the issue. We aim to respond within **three business days**.

For details on how we triage and patch dependencies see the
[patch and upgrade guide](docs/security/patch-flow.md).

## Security Scans

Our CI pipeline runs **Bandit**, **pip-audit**, and **npm audit**. Containers are scanned with Trivy and Grype when available.

## Patch Policy

If **pip-audit** or our nightly security workflow flags a high-severity vulnerability we issue a hotfix within **48 hours**. Medium issues are addressed in the next regular release.

## Disclosure Guidance

We encourage responsible disclosure. Please avoid posting public issues for new vulnerabilities until we have published a fix. Coordinate with us via [GitHub private vulnerability reporting](https://github.com/eputnam77/DocReview360/security/advisories/new).

Automated Bandit scan results are generated by `scripts/run-pip-audit.py` and the CI nightly workflow.
Dependency-Check runs when the tool is available; network restrictions may skip this step.

## Dependency Pinning Strategy

- Python dependencies are pinned in `poetry.lock` and `requirements*.txt` for reproducible installs.
- Frontend dependencies are pinned in `frontend/package-lock.json`.
- Security updates are triaged via `pip-audit`, `npm audit`, and CI scanning.
- High-severity findings are patched on an expedited release path per the patch policy above.
